## 4. Ответы на контрольные вопросы

### 1. Что такое ветка в Git и для чего она используется?
**Ответ:** Ветка (branch) в Git — это легковесный подвижный указатель на конкретный коммит в истории изменений. Ветки используются для изоляции разработки различных функциональностей (features), исправления ошибок (bugfixes) или проведения экспериментов. Это позволяет нескольким разработчикам параллельно работать над проектом, не нарушая стабильность основной ветки (`main`/`master`), а затем безопасно сливать готовые изменения.

### 2. Как создать Pull Request на GitHub?
**Ответ:** 
1. Создать локальную ветку, внести изменения, закоммитить их и отправить на GitHub с помощью команды `git push origin <branch-name>`.
2. Перейти на страницу репозитория на GitHub.
3. Нажать на появившуюся кнопку **"Compare & pull request"** (или перейти во вкладку **"Pull requests"** → **"New pull request"**).
4. Выбрать базовую ветку (base branch, например, `main`) и сравниваемую ветку с изменениями (compare branch).
5. Заполнить заголовок (title) и подробное описание изменений (description).
6. Нажать **"Create pull request"**.

### 3. Что такое конфликт слияния и как его разрешить?
**Ответ:** Конфликт слияния (Merge Conflict) возникает, когда Git не может автоматически объединить изменения из двух веток. Чаще всего это происходит, если в обеих ветках были изменены одни и те же строки одного и того же файла либо если один участник удалил файл, а другой изменил его.

**Алгоритм разрешения конфликта:**
1. Подтянуть актуальную целевую ветку (`git checkout main && git pull`).
2. Переключиться на рабочую ветку и попытаться слить целевую: `git checkout <feature-branch> && git merge main`.
3. При возникновении конфликта открыть проблемные файлы в текстовом редакторе.
4. Найти блоки маркеров:
   - `<<<<<<< HEAD` — версия в текущей ветке;
   - `=======` — разделитель версий;
   - `>>>>>>> <branch-name>` — версия из вливаемой ветки.
5. Отредактировать текст, оставив корректный итоговый вариант, и удалить служебные маркеры.
6. Добавить файл в индекс и завершить слияние коммитом:
   ```bash
   git add <file>
   git commit -m "Разрешен конфликт слияния"
   git push origin <feature-branch>
   ```
7. После отправки изменений статус PR на GitHub автоматически обновляется до доступного для слияния.

### 4. Какие команды используются для добавления изменений в репозиторий?
**Ответ:** Основная последовательность команд:
- `git status` — просмотр статуса измененных, неотслеживаемых и подготовленных файлов.
- `git add <file>` (или `git add .`) — добавление измененных файлов в область подготовленных файлов (staging area / индекс).
- `git commit -m "Сообщение"` — фиксация изменений из индекса в локальный репозиторий с поясняющим сообщением.
- `git push origin <branch-name>` — отправка локальных коммитов в удаленный репозиторий на ветку `<branch-name>`.

### 5. Зачем нужны Pull Requests в командной разработке?
**Ответ:** Pull Requests (PR) играют важнейшую роль в командной разработке:
1. **Код-ревью (Code Review):** позволяют коллегам просматривать предлагаемые изменения, находить ошибки, уязвимости и архитектурные недочеты до их попадания в стабильную ветку.
2. **Обсуждение и обратная связь:** предоставляют платформу для дискуссий по конкретным строкам кода прямо в веб-интерфейсе.
3. **Автоматизированное тестирование (CI/CD):** позволяют запускать автоматические тесты, сборку и линтеры при каждом изменении в ветке PR.
4. **Контроль качества и безопасности:** предотвращают непреднамеренное повреждение основной кодовой базы, гарантируя, что код соответствует стандартам команды.
5. **Прозрачность и документирование:** формируют структурированную историю обсуждений и причин внесения тех или иных правок в проект.
